## 設計方針
ステージ進行を中央管理するため、GeneralStageManagerを基底クラスとして設計し、
各ステージマネージャーがこれを継承する構造にしています。

各オブジェクトの状態変化はイベントとして扱い、ステージマネージャー側で進行管理を行うことで、
- ギミック追加時の影響範囲の限定<br>
- ステージ構成変更への柔軟対応<br>
- 共通処理の再利用性向上<br>
以上を意識した設計にしています。

---

## 工夫点
- ステージ全体を4分割し、独立した部屋単位で設計<br>
- 共通ステージロジックを基底クラスへ集約<br>
- 各ステージ固有ギミックは継承クラスで実装<br>
- ギミック発動はゲームマネージャー側で一元管理<br>

設計上の責務分離を意識し、拡張しやすい構造を目指しました。

---

## 課題・改善点
- 現在は各継承したスクリプトのUpdate関数によりゲームフローを制御しているため、 基底クラス内でUpdate関数を使用した統一的な制御へ改善したい。
- カメラ遷移が各ロジック関数内で設計させているので、これを一つの関数にして管理。
- プレイヤーの攻撃とエネミーの攻撃を共通のインターフェースを設計することでより、設計しやすくする。

現状の課題を踏まえ、今後は設計の責務分離と再利用性の向上を意識して改善していきます。
